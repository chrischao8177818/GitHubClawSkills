# 料理影片摘要知識庫

把料理影片、逐字稿、Shorts / Reels 文字、食譜文章，整理成可長期查詢的私人料理知識庫。

## 目的

- 先呼叫 `gemini-summary` 取得摘要，再把結果整理成固定欄位的 Markdown 食譜。
- 把口語或零散內容轉成固定欄位的 Markdown 食譜。
- 讓每道料理可以被搜尋、分類、比對、重用。
- 讓你可以用關鍵字找回已整理好的料理做法。

## 輸出與查找責任

- `artifacts/{issue-comment-id}/result.md`：任務回報、整理紀錄、驗證結果與執行說明。
- `recipes/`：真正的料理知識庫成品，位置固定在 repo 根目錄下的 `recipes/`。
- skill 內的 `recipes/`：只保留占位或範本用途，不是正式輸出目錄。

## 何時使用

當使用者出現以下情境時，優先使用這個 skill，並把它當成主要入口：

- 要把影片、PDF、食譜文章變成食譜檔。
- 要先用 `gemini-summary` 摘要，再整理成標準食譜格式。
- 要建立可搜尋的料理知識庫。
- 要從 YouTube / Shorts / Reels / 食譜文章萃取料理步驟與標籤。
- 要查詢或新增某道料理到 repo 根目錄的 `recipes/`。
- 要列出目前有哪些料理摘要。
- 要找某個菜名、某種食材、某種烹飪方式的既有整理。
- 使用者只輸入短別名時，也直接視為入口：
  - `cooking {網址}`
  - `煮飯 {網址}`
  - `做菜 {網址}`
  - `料理 {網址}`
- 使用者只下簡短查找指令，例如：
  - `列出目前所有清單`
  - `幫我找「客家小炒」的作法`
  - `找所有炒菜`
  - `列出電鍋料理`
  - `找番茄相關料理`

## 兩種模式

### 1. 摘要模式

用途：把新來源先摘要，再整理成可查詢的食譜條目。

輸入優先順序：

1. Gemini Summary 產生的影片摘要
2. YouTube 影片逐字稿
3. Shorts / Reels 文字內容
4. 食譜文章
5. 使用者手動補充內容

工作流程：

1. 先呼叫 `gemini-summary`，再讀取可用來源，優先採信 Gemini Summary。
2. 萃取菜名、食材、調味、工具、步驟、保存方式與情境。
3. 若資訊不完整，保留缺漏，不要硬補精確數字。
4. 可合理推定的烹飪順序，標記為 `AI 推測`。
5. 依食材、工具、情境自動分類並加上搜尋標籤。
6. 依檔名規則輸出成單一道料理一個檔案。
7. 若來源資訊足夠可形成料理條目，必須同步產出一份料理 Markdown 檔到 repo 根目錄的 `recipes/`。
8. 仍需同時寫出 `artifacts/{issue-comment-id}/result.md` 作為本次任務回報。

### 2. 查找模式

用途：從現有知識庫找回你想要的料理摘要或做法。

查找優先順序：

1. `recipes/`
2. `artifacts/`

查找原則：

- 先找檔名、標題、摘要、標籤、關鍵字。
- 命中後，優先完整呈現原始 `.md` 內容，不要再把結果二次摘要。
- 只有在使用者明確要求「濃縮」、「列重點」、「只看摘要」時，才把命中內容縮短。
- 若命中多筆，先完整列出最相關的少量結果，再視需要補其他筆。
- 若找不到，明確說明沒有命中，並建議改用更精確的關鍵字。
- 若查詢是「炒菜」「熱炒」「快炒」這類做法，優先回傳與炒鍋、快炒步驟、火候重點相關的結果。
- 使用者若只輸入簡短中文指令，視為查找模式，不要要求對方補上搜尋路徑。

## 查找時可回答的內容

- 列出目前有哪些料理
- 查某一道菜的做法
- 找某個食材可以做哪些料理
- 找某一種工具的料理，例如電鍋、氣炸鍋、炒鍋
- 找某一種情境的料理，例如便當菜、快速料理、家常菜
- 比對多道相似料理

## 快捷指令範本

以下這些短句都應直接進入查找模式：

- `列出目前所有清單`
- `幫我找「客家小炒」的作法`
- `找所有炒菜`
- `列出電鍋料理`
- `找番茄相關料理`
- `找所有高蛋白料理`
- `查「鮮魚炊飯」`
- `比對客家小炒和鮮魚炊飯`

## 必填欄位

每篇食譜都要包含以下欄位，順序固定：

1. 菜名
2. 一句話摘要
3. 來源資訊
4. 分類資訊
5. 食材清單
6. 調味料
7. 烹飪工具
8. 詳細步驟
9. 關鍵技巧
10. 常見失敗原因
11. 替代方案
12. 保存方式
13. AI 搜尋標籤

## 寫作規則

- 全部使用繁體中文。
- 全部使用 Markdown。
- 不要自行虛構精確份量。
- 若 Gemini Summary 沒寫清楚，明確標記 `摘要未明確說明`。
- 若來源之間衝突，以逐字稿為準。
- 若步驟需要補順序，可補，但要標記 `AI 推測`。
- 料理名稱、食材、工具與情境要盡量維持原始語意，不要改寫到失真。

## 檔名規則

使用這個格式：

`【類型】料理名_主要食材_烹飪方式.md`

範例：

- `【家常菜】番茄炒蛋_雞蛋_平底鍋.md`
- `【減脂】氣炸雞胸肉_雞胸肉_氣炸鍋.md`

## 來源資訊處理

在來源資訊區塊中，至少保留以下欄位：

- 原始影片連結
- Gemini Summary 來源
- 整理日期

如果沒有連結或日期，寫 `摘要未明確說明`。

使用者若直接輸入來源網址，或是使用類似 `cooking-video-summary <url>` 的短指令時，視為摘要模式入口，先呼叫 `gemini-summary`，再進行食譜整理。
